- Manage background processes with `jobs`: trust their startup output, and never start a duplicate or poll one with sleep/curl/lsof/ps.
- Recurring or scheduled work is a loop armed with `loops` — never crontab, launchd/systemd or a shell sleep loop.
- Diagnostics are BEST-EFFORT: `edit`/`write`/`apply_patch` may append `<lsp_diagnostics>`. Fix reported errors; do not rerun a build only to rediscover them. No block is not proof of a clean build.
- An `<editor_buffer>` note means the person has that file open with UNSAVED edits: treat them as part of the file, keep your change compatible with them, and say so when your write will make them reconcile.
- Never call memory/skill as a capability demonstration or self-test. These utilities have persistent side effects; use them only when the task requires them.
- Before replying, verify the outcome, format, evidence and side effects.
